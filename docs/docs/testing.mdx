### Built in mocks

This library includes a built in mock for Jest. It will use the following metrics by default:

```tsx
{
  frame: {
    width: 320,
    height: 640,
    x: 0,
    y: 0,
  },
  insets: {
    left: 0,
    right: 0,
    bottom: 0,
    top: 0,
  },
}
```

To use it, add the following code to the jest setup file:

```tsx
import mockSafeAreaContext from 'react-native-safe-area-context/jest/mock';

jest.mock('react-native-safe-area-context', () => mockSafeAreaContext);
```

To have more control over the test values it is also possible to pass `initialMetrics` to
`SafeAreaProvider` to provide mock data for frame and insets.

```tsx
export function TestSafeAreaProvider({ children }) {
  return (
    <SafeAreaProvider
      initialMetrics={{
        frame: { x: 0, y: 0, width: 0, height: 0 },
        insets: { top: 0, left: 0, right: 0, bottom: 0 },
      }}
    >
      {children}
    </SafeAreaProvider>
  );
}
```

### Transforming the package with Jest

Starting with version 6, this library is published as ESM only. By default, [Jest does not transform files inside `node_modules`](https://jestjs.io/docs/configuration#transformignorepatterns-arraystring), so loading the package or its mock fails with:

```
SyntaxError: Cannot use import statement outside a module
```

If you use the React Native Jest preset (`react-native` or `@react-native/jest-preset`), add `react-native-safe-area-context` to `transformIgnorePatterns` in your Jest config:

```js
transformIgnorePatterns: [
  'node_modules/(?!((jest-)?react-native|@react-native(-community)?|react-native-safe-area-context)/)',
],
```

If you already customize `transformIgnorePatterns`, add `react-native-safe-area-context` to your existing pattern instead. The `jest-expo` preset already transforms this package, so Expo projects don't need any change.
