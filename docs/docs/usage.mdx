This library has 2 important concepts, if you are familiar with [React Context](https://react.dev/learn/passing-data-deeply-with-context) this is very similar.

### Providers

The [SafeAreaProvider](/api/safe-area-provider) component is a `View` from where insets provided by consumers are relative to. This means that if this view overlaps with any system elements (status bar, notches, etc.) these values will be provided to descendent consumers. Usually you will have one provider at the top of your app.

### Consumers

Consumers are components and hooks that allow using inset values provided by the nearest parent provider. Values are always relative to a provider and not to these components.

- [SafeAreaView](/api/safe-area-view) is the preferred way to consume insets. This is a regular `View` with insets applied as extra padding or margin. It offers better performance by applying insets natively and avoids flickers that can happen with the other JS based consumers.

- [useSafeAreaInsets](/api/use-safe-area-insets) offers more flexibility, but can cause some layout flicker in certain cases. Use this if you need more control over how insets are applied.

### Keyboard handling

The safe area insets do not include the software keyboard. It is recommended to use [react-native-keyboard-controller](https://github.com/kirillzyusko/react-native-keyboard-controller) to handle those.

#### Android `windowSoftInputMode`

The [`windowSoftInputMode`](https://developer.android.com/guide/topics/manifest/activity-element#wsoft) of your activity in `AndroidManifest.xml` does not change the insets, the keyboard is never part of them. It can change the size of the `SafeAreaProvider`, which is reported by [useSafeAreaFrame](/api/use-safe-area-frame):

- When the app is not drawn edge-to-edge, `adjustResize` shrinks the window while the keyboard is open, so the provider frame gets shorter.
- When the app is drawn edge-to-edge, `adjustResize` does not resize the window. The provider keeps its full height and the keyboard covers its bottom part. Android 15 and newer draw apps that target SDK 35 or higher edge-to-edge.
